# 出自監査サマリ（Step 2 結果）

実施日: 2026-08-22 / 対象: `配布パッケージ_Man_v1.2.0/models/MaleAnatomy_v1.2.0.obj`（939オブジェクト・16,195,795頂点）
比較対象: BodyParts3D v4.0（NBDC LSDB Archive、CC BY 4.0、2026-08-22取得）

再現手順:
```
python scripts/provenance/build_bp3d_index.py      # BP3D OBJヘッダ2234件 -> bp3d_index.json
python scripts/provenance/scan_obj_export.py <配布OBJ> refs/BodyParts3D_v4.0/man_geom.json
python scripts/provenance/match_geometry.py        # 名前突合＋相似変換の推定
python scripts/provenance/audit_bp3d.py            # 幾何のみで全939を突合 -> refs/provenance_audit.csv
python scripts/provenance/compare_surface.py       # 代表6パーツの面の一致度
```

## 1. 座標系の対応

BP3D(mm, z-up) から製品座標へは **軸入替 (x, z, -y)・一様スケール 0.000973・平行移動** の
相似変換1つで載る。510パーツの重心で最小二乗フィットし残差 RMS 15.7mm。
→ 製品は BP3D の座標系をほぼそのまま受け継いでいる（部位ごとの独自再配置はされていない）。

## 2. 全オブジェクトの判定（refs/provenance_audit.csv）

| 判定 | 件数 | 割合 |
|---|---|---|
| BP3D由来(強) 重心25mm以内・サイズ比0.85〜1.18 | 743 | 79.1% |
| BP3D由来(可) 重心60mm以内・サイズ比0.7〜1.45 | 167 | 17.8% |
| 要確認 | 27 | 2.9% |
| 自作（下着2種） | 2 | 0.2% |

**BP3D由来と判定できたもの合計 910 / 939 = 96.9%。always3d が独自に作ったと見られるメッシュは検出されなかった。**

「要確認」27件の内訳は、いずれも *BP3Dに無い形* ではなく **粒度の違い**:
- 複合パーツ（広背筋・腹直筋・腰方形筋・側頭筋・肺動脈・肺静脈・気管支など）を製品が1メッシュに統合しているため、BP3Dの単一エレメントと1対1にならない
- `外肋間筋_上部` `内肋間筋_上部` `最内肋間筋_上部` は **ユーザー自身が v0.1.0 で第六肋骨ラインで上下分割したもの**（自作の分割）

名前照合（英名の語集合）と幾何照合が同じBP3Dパーツを指した割合: **442 / 510 = 86.7%**（不一致は左右対や部分名の揺れ）。

## 4. ここから言えること／言えないこと

**言えること**
- 製品のジオメトリは BodyParts3D の同一セグメンテーション（同一被検者の同一区分け）である
- always3d が独自に作成・リトポしたメッシュは見つからなかった（下着2件を除き全て BP3D に対応先がある）
- 日本語名・ふりがなも BP3D の `isa_parts_list.txt`（kanji/kana列）由来。`仙骨;仙椎[1－5]` `陰毛;カクシゲ` `口唇nsn;クチビルnsn` のようなセミコロン区切り表記はBP3D固有の書式

**言えないこと（実測できていない）**
- 製品の密度（BP3D v4.0 配布版の5〜15倍）がどこから来たか。
  LSDB Archive が配布するのは `_99`（ポリゴン削減率99%）版のみで、それ以外の解像度は提供されていない
  （`obj_95` `obj_50` `obj` 等のURLはいずれも 302 で存在しない。ディレクトリ一覧も `_99` のみ）
- 旧本家 https://lifesciencedb.jp/bp3d/ (Anatomography) は **v4.3 / v5.0 / v5.3 / heart5.0i** など
  アーカイブに無い新しい版を保持している（ページ内 `version2tg` より）。筋のズレはこの版差で説明がつくが、
  **同サイトのライセンス表記は今も「表示-継承2.1 日本」**

→ **CC BY 4.0 の relicense が及ぶ範囲（v4.0アーカイブのみか、BodyParts3D全体か）が未確定。**
   これが確定しないと「always3dを迂回できる」と断言できない。DBCLS への照会で確定させる。

## 5. Blender 上での実物比較（2026-08-22 追加）

`scripts/provenance/render_compare.py` で製品メッシュと BP3D v4.0 メッシュを同一カメラで撮影し、
`scripts/provenance/make_contact_sheet.py` で「製品 | BP3D | 重ね」の1枚に合成した。
出力: `refs/BodyParts3D_v4.0/compare_sheets/`

- **軸合わせは恒等変換で成立**（24通りの総当たりで perm=(0,1,2)・符号(1,1,1)・スケール≈0.001 が最良）。
  つまり Blender 内で製品と BP3D は**同じ向き・同じ座標系**を共有しており、mm→m の倍率だけが違う
- 点→三角形の厳密距離（`scripts/provenance/deviation_map.py`）:

| パーツ | 製品/BP3D頂点 | 中央値 | 95% | 最大 |
|---|---|---:|---:|---:|
| 下顎骨 | 10,980 / 2,845 | 0.08mm | 0.19 | 2.03 |
| 右上腕骨 | 8,707 / 2,233 | 0.10mm | 0.28 | 4.41 |
| 右肩甲骨 | 56,704 / 13,118 | 1.62mm | 6.36 | 8.04 |
| 右小胸筋 | 33,001 / 6,741 | 1.61mm | 8.07 | 12.71 |
| 右大胸筋胸肋部 | 24,958 / 5,480 | 3.51mm | 6.47 | 8.54 |
| 右腓腹筋外側頭 | 27,026 / 1,748 | 3.73mm | 11.31 | 15.51 |

- **骨は 0.08〜0.10mm＝実質同一の面**
- **筋のズレは「編集の形」をしていない**。目視でも、製品側は筋線維の溝が刻まれているのに対し
  BP3D `_99` 版は同じ輪郭のまま溝を潰した平滑な塊になっている。ズレは溝に沿った縞、
  あるいは端へ向かう連続勾配として出ており、局所的なパッチ（＝手編集の痕）は見当たらない
- 結論: **同一セグメンテーションの解像度違い**。BP3D 配布版が削減率99%で細部を失っているだけ

## 6. 「密度はユーザー編集によるものか」の決着（2026-08-22）

疑問: 製品の筋メッシュが BP3D 配布版の5〜15倍密なのは、こちらの編集で増えたのではないか。

検証: **always3d の未加工配布FBXを直接読んで頂点数を突き合わせた**
（`scripts/provenance/dump_fbx_counts.py`。元FBXは一度も編集していないオリジナル）。

```
blender -b --factory-startup -P scripts/provenance/dump_fbx_counts.py -- <fbx> <out.json>
```

| 比較 | 結果 |
|---|---|
| `3DAnatomyman_Japanese_0_全て.FBX`（934メッシュ）と製品(939)で対応がついた | **931個** |
| そのうち**頂点数・面数とも完全一致** | **931 / 931 = 100.00%** |
| 異なるもの | **0件** |

※FBX側は63字で切り詰められハッシュ接尾辞 `_xxxxxxx` が付くものが212件あるため、前方一致で突合した。
部分FBX（筋肉445/骨格272/臓器211/外皮毛髪6）でも同様に一致（種子骨の1件だけ不一致に見えたのは
こちらの名前正規化が左右を衝突させていたためで、実際は 328=328・350=350 で一致）。

例: 右小胸筋 33,001頂点（配布FBX）= 33,001頂点（製品）／右腓腹筋外側頭 27,026 = 27,026

**配布FBXに対応が無い製品オブジェクトは次の8個だけ＝すべて自作:**

| オブジェクト | 由来 |
|---|---|
| `下着_皮膚用(Brief_skin)` / `下着_筋肉用(Brief_muscle)` | Man v1.2.0 で追加した自作メッシュ |
| `外肋間筋_上部/_下部`・`内肋間筋_上部/_下部`・`最内肋間筋_上部/_下部` | v0.1.0 で肋間筋3個を第六肋骨ラインで上下に分割したもの（元3個→6個） |

934 − 3(分割前の肋間筋) = 931、931 + 8 = 939 で員数が完全に合う。

→ **密度はalways3dの配布物そのままであり、こちら側の編集で増えたものではない。**
　 したがって「BP3D の高解像度版を always3d が入手して配布している」という理解になる。
　 LSDB Archive が配布する `_99` は削減率99%版であり、これとは別解像度。

## 7. 女性版の扱い（2026-08-22 ユーザー判断）

女性版は男性版（Man_All）を元に女性化変形して作ったものなので、**出自は男性版と同一**。
個別の監査は不要とし、本レポートの結論をそのまま女性版にも適用する。

（女性版は頂点座標が変形されているため頂点数一致では判定できず、形状距離での判定になる。
　必要が生じたら `scripts/provenance/` の一式で同じ検証は実行できる。）

## 8. 結論：ライセンスは変更できるか

**「always3d 由来という制約は外せる見込みが高い。ただし1点だけ未確定が残っており、現時点では確定していない。」**

外せる根拠（実測で確定済み）:
- always3d はジオメトリを1頂点も足していない（931/931 完全一致、自作8個を除く）
- 日本語名・ふりがなも BP3D の `isa_parts_list.txt` 由来
- BodyParts3D の権利者 DBCLS 自身が 2025/02/27 に CC BY 4.0（継承なし）へ変更している
  → 権利者が現に BY で提供している以上、SA を課しているのは中間の always3d だけ

未確定（外部の運用なので実測不能）:
- 製品が載っているのは **LSDB Archive が配布していない高解像度版の BP3D**。
  CC BY 4.0 の許諾が「BodyParts3D という著作物全体」に及ぶのか、
  「アーカイブが配布している v4.0 `_99` ファイル」に限るのかが不明。
- これは DBCLS しか答えられない。`ライセンス照会_DBCLS.md` の質問3がこれを聞くもの。

**この回答が出るまでライセンス表記は変更しない。**（見込みで変えると、後から覆ったとき
既に頒布した分を回収できないため。CC は一度与えた許諾を撤回できない。）

## 9. 高解像度版の出どころが判明（2026-10-06）

DBCLS 箕輪さんの回答（2026-10-06）: **生命科学系データベースアーカイブからダウンロードできるデータは CC BY 4.0**、
Anatomography 側の最新データは CC BY-SA 2.1 JP。ライセンスページの対象は「本データベース」全体。

アーカイブを総ざらいしたところ、`LATEST/`（v4.0 `_99` のみ）以外に旧リリースのフォルダが残っていた
（https://dbarchive.biosciencedbc.jp/data/bodyparts3d/ 配下）。

| フォルダ | 中身 |
|---|---|
| 20080812 / 20090209 | stl・vtk の 0.1 / 0.01 版 |
| 20100816 | `BodyParts3D_2.0_obj_95.zip` / `_99` |
| 20110915 | **`BodyParts3D_3.0_obj_95.zip`（547MB）** / `_99` |
| 20130619 (=LATEST) | v4.0 `_99` のみ |

`refs/BodyParts3D_v3.0_95/` に 3.0 `_95` を取得して always3d 配布FBX（`always3d_fbx_0_全て.json`）と突合:

- **934 / 934 メッシュで頂点数・面数が完全一致**、bbox の各辺も全件 3mm 以内（m→mm 換算）
- 代表6パーツ: 下顎骨 10,980 / 右上腕骨 8,707 / 右肩甲骨 56,704 / 右大胸筋胸肋部 24,958 / 右小胸筋 33,001 / 右腓腹筋外側頭 27,026 — 製品と完全一致

→ **always3d の配布物は、アーカイブの BodyParts3D 3.0 `_95` を FBX に変換しただけのもの。**
§4「言えないこと」の「密度がどこから来たか」はこれで決着（Anatomography の新版ではない）。
正本はアーカイブから直接取得した `refs/BodyParts3D_v3.0_95/BodyParts3D_3.0_obj_95.zip`（2026-10-06取得）とする。
なお OBJ ヘッダには `CC Attribution-Share Alike 2.1 Japan` と書かれているが、v4.0 と同じく作成当時の表記の残り（DBCLS回答でアーカイブ配布分は BY 4.0）。
